{# partials/timescale_compression_group_list.html Swapped into #compression-groups-container on page load and again after every "Rebuild Compression" click (see timescale_rebuild_compression .html). Sibling of partials/timescale_rollup_view_list.html and deliberately styled to match it line-for-line rather than inventing a new visual language for this screen. Context: groups — [{protocol_name, wide_table_name, total_chunks, compressed_chunks, size_bytes, size_display, raw_size_bytes, raw_size_display, tables: [{table_name, granularity, total_chunks, compressed_chunks, size_bytes, size_display, raw_size_bytes, raw_size_display}, ...]}, ...] as returned by services/bridge_service .list_compression_groups. `protocol_name` is "shared_narrow" for the shared narrow-table group; every other group is one wide-table protocol's own raw table + hourly/daily/weekly/monthly rollup stack. One checkbox per GROUP, not per table — same reasoning as the rollup view list: a compression rebuild always acts on a whole group's tables together (see RollupManager.rebuild_compression), so there's nothing finer-grained to select. Checkboxes default checked (rebuild everything unless the admin opts a group out) and are read by triggerRebuildCompression() in timescale_rebuild_compression.html when the button is pressed — this partial itself makes no request and stages nothing. Unlike the rollup view list's per-view `status` (OK / needs rebuild / missing), a table here doesn't have a pass/fail state to color — being compressed isn't right or wrong, it's just a number. So each row is neutral, and only the group header line calls out the compressed/total ratio and total size up front. Styling notes (mirrors timescale_rollup_view_list.html / timescale_field_checklist.html): - Row text uses paired light/dark classes (text-mpg-500 dark:text-mpg-100, etc.) for the same reason as those two partials — the app is used in both light and dark mode, and a single shade tuned for one background reads as low-contrast (or outright unreadable) on the other. This partial previously used single-shade classes (text-mpg-200 / text-mpg-400) that only had contrast against a dark background; on light mode those rendered as pale gray on white, effectively unreadable. Fixed here by adopting the same paired classes as the rollup partial throughout. - `w-auto` on is required (not optional) to override mpg.css's global `table { width: 100%; }` rule — see the equivalent note in timescale_field_checklist.html / timescale_rollup_view_list.html. #}
