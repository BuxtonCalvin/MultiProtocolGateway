Context: storage — dict from services/bridge_service.get_influxdb_storage(). One template serves both transports, which return the same field names but populate different subsets: - v1 (influxdb_out): items_label="Measurements", sample_item / sample_item_approx_rows (one sampled measurement's approximate row count), retention_policies, optional data_dir size. has_table_stats is always False and table_stats/columns/heap_profile are always empty/None — v1 has no equivalent to v3's system.chunks or information_schema.columns. - v3 (influxdb3_out): items_label="Tables", has_table_stats=True with a real per-table row_count/file_size/memory breakdown from system. chunks (table_stats), a column count per table folded in from information_schema.columns (columns_by_table), optional object_store_ dir size (also surfaced via data_dir/data_dir_size_display, same field names as v1's data_dir), and an optional heap_profile probe. sample_item / retention_policies are always None/empty on v3. heap_profile, when present, is a reachability probe only — see influxdb3_out._probe_heap_profile for why the raw pprof/protobuf response is never decoded into an actual memory-usage figure here. `error`, if set, is shown inline rather than blanking the whole card, since e.g. a schema query failing shouldn't hide chunk stats that already succeeded. Purely observational — nothing here is clickable, and none of these values can be edited from this card.
