{# partials/timescale_field_checklist.html Swapped into #timescale-fields-container when a wide table is selected. Context: protocol_name, wide_table_name, fields — [{metric_name, column_name, data_type, checked, stale}, ...] in alphabetical column_name order. `stale` (services/bridge_service._active_metric_names_for_protocol) means the column's metric_name is no longer produced by the protocol's live variable_mask/variable_screen config — the same "column exists in the wide table but the scrape data doesn't have it" condition timescaledb._validate_wide_row otherwise only surfaces as a warning log line. Those rows render their column name in `text-danger` (red) with a small caption, as a hint for what's likely safe to check off — the admin still has to check the box and commit, nothing is pre-selected. Checking a box PATCHes /api/timescale/.../stage to add it to the in-memory staged-deletion set (services/bridge_service.py) — no ALTER TABLE happens here. hx-swap="none" because the checkbox itself is the only thing that needs to reflect the change; the header's Commit / Discard buttons pick up the new dirty state via base.html's htmx:afterRequest -> refreshState() listener. Styling notes (mirrors protocol_table.html): - Row text uses paired light/dark classes (e.g. "text-mpg-500 dark:text-mpg-100") rather than a single shade — the app is used in both light and dark mode, and a shade tuned for a dark background reads as low-contrast/washed-out on the light background. Only the header row's classes are fixed (bg-mpg-800 / text-mpg-50), since the header bar itself stays dark in both themes. - The table has no fixed widths and Column/Data Type cells use whitespace-nowrap, so the browser's default auto table layout sizes each column to its longest cell content (plus the cell's px-3 padding) rather than stretching to fill the pane. Note: mpg.css has a global `table { width: 100%; }` rule, so `w-auto` on here is required (not optional) to override it — a class selector beats that bare element selector on specificity, but simply omitting a width class isn't enough since the global rule still applies by default. #}
